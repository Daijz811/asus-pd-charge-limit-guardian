# 调查与验证记录

## 适用对象

- 维护者设备：ASUS ROG Zephyrus G16 / 幻16（2023），`GU603VV`。
- 前期调查及原项目 README 标注 BIOS：`GU603VV.315`。
- 电源：240 W 圆口适配器、约 100 W USB-C PD；以外部数显线观察输入功率。
- 本仓库没有本板原理图、带网络的 BoardView、原始后续总线日志或长时间测试曲线。以下明确区分前期观察、维护者提供的后续结果和待验证解释。

## 修复前

2026-11-03 至 2026-11-07 的调查记录包括：

- 80% 上限下，电量下降阶段 79% 时 PD 输入仍为 0 W，78% 时恢复约 91.6 W；回充到 79% 时约 75–90 W，80% 时又降为 0 W。
- 电量高于保护上限时，不拔 PD 线，仅把上限临时提高到 100%，可恢复输入；这是调查对照，不是最终解决方案。
- 两个支持 PD 的 USB-C 端口均观察到同类现象。
- 圆口供电达到上限后电量基本稳定，表现不同。

这组观察说明停充控制与断供相关，不能单凭它认定电池只能充不能供、具体场管接线或芯片型号。

## 固件静态线索

前期离线研究追踪到：

1. ACPI 限充命令传递到 EC。
2. 停充状态下存在电流目标清零并写至 `0x14` 的路径。
3. 限充启用且满足特定条件时，固件取电池当前电压形成系统电压目标，后续写至 `0x15`。关键路径包含 EC 文件偏移 `0x1354b`。

这些是候选控制链。静态分析未证明所有运行时分支和实际电路拓扑，也未产生可用补丁。后续通过 WMI 运行时访问与实测推进，才得到本工具使用的参数组合。

## 原始修复的报告结果

维护者于 2026-11-15 提供了原项目和已解决问题的反馈。原项目 README 记录：

| 同类停充状态 | 外部 PD 输入 | 电池电流 |
| --- | --- | --- |
| 修复前 | 0 W | 约 2820–3007 mA 放电 |
| 修复后 | 恢复至约 40 W 以上的整机功耗水平 | 约 15–27 mA |

原脚本在 PD 单独接入且 `State=6` 时，将零电流目标改为 `0x0040`，并把过低的系统电压目标提高到 17000。GUI 与后台 worker 分离，支持启停和当前用户登录后自启。

**这些结果支持：至少这台机器的症状存在可用的软件运行时绕行方案。** 它们没有证明长期零电池电流、所有负载下都不放电、完整硬件隔离旁路，或所有 GU603 系列都适用。

## 芯片与机理的证据边界

原项目报告：一个总线通道读到 `0x0040:0x0038`，另一个读到 `0x0049:0x000C`；脚本只对后者检查和干预。仓库当前没有后续原始寄存器抓取文件，故这里按项目报告记录，不把它等同独立复测。

Renesas 多个 ISL923x 器件使用相似寄存器布局；厂商和设备 ID 不足以唯一确认 ISL9238C 或 ISL9241 等具体型号。准确识别还需要芯片丝印、对应手册和板级连接。前期固件字符串也不足以替代物理 EC 型号确认。

`0x14=0` 是否关闭特定配置下的转换级，以及改变 `0x15` 如何改善该板供电，应以本板进一步的分离变量试验为准。**本仓库不把“所有此类芯片写零都会停止整机供电”当作通用结论。** 同样，8 mV 量化确实存在于相关系列手册中，但不能仅凭向下量化就断言它是持续放电的唯一原因。

名义电流还取决于实际采样电阻与器件变种。微小非零电池电流、仪表刷新和功耗波动都需要考虑；本项目没有电池寿命改善百分比或完全消除微循环的长期证明。

## v0.2.1 发布检查

在保留原修复参数、布局和主要流程的基础上增加：

- 启动时检查 GU603VV / BIOS 315，再访问固定 EC 地址。
- 邮筒繁忙与事务完成超时均中止；不返回残留读数。
- 根据 ACPI EC-SMBus 状态字段检查错误码，不强制要求某一 DONE 标志组合。
- 对 `0x14` / `0x15` 写入做读回核对；底层入口同样限制目标和值。
- 邮筒锁等待失败不再静默返回。
- 通信异常停止守护并尝试恢复，面板保留错误；关闭操作即使恢复失败也移除自动启动任务。
- 面板依据读回值显示参数状态，不依据 `State=6` 直接声称 PD 已断流或已恢复实际供电。

新增逻辑的测试使用模拟对象。没有在发布过程中运行主脚本、调用真实 EC WMI、写充电芯片或创建计划任务。模型/BIOS检查、睡眠恢复、登录自启与长期运行仍需维护者对公开版重新验证。进程间锁不构成与固件的全局互斥。
