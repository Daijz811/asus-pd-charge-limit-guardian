# 调查记录

## 现象与实测

GU603VV / BIOS 315，使用约 100 W USB-C PD。设置 80% 电池保护上限后，达到上限时 PD 输入降为 0 W；电量下降至约 78% 后恢复充电。两个 USB-C 口均观察到类似现象，圆口供电达到上限后则能继续供电。

原方案（17000 mV）记录的修复效果：

| 停充状态 | 外部 PD 输入 | 电池电流 |
| --- | --- | --- |
| 修复前 | 0 W | 约 2820–3007 mA 放电 |
| 修复后 | 约 40 W 以上 | 约 15–27 mA |

## 分项试验记录

2026-11-15 的维护者记录包含以下短时试验：

| 参数或操作 | 观察结果 |
| --- | --- |
| `0x14=0`，将 `0x15` 提至 17600，持续20秒 | 电池仍约 2.5–2.7 A 放电。 |
| `0x14=0x0040`，电压目标跟随 EC 原值 | 外部 PD 输入约20 W，电池放电电流逐渐下降。 |
| 保持 `0x14=0x0040`，持续刷新 `0x15=17000` | 外部 PD 输入约40 W；短时电池电流读数降至几十 mA。 |
| 前10秒应用组合参数，后20秒停止写入 | 电压目标被 EC 改回电池电压附近，电池电流读数逐渐升至约499 mA。 |

这些对照支持组合参数和持续守护的作用。

## 充电限流原理与参数选择

**电流限制怎样生效。** [Renesas ISL9238A 手册第21、23页](https://www.renesas.com/en/document/dst/isl9238a-datasheet)说明，充电电流环利用采样电阻两端压差调节电流：`0x14` 设置充电电流限值，`0x15` 设置最高充电电压或系统调节电压。电流目标和电压目标共同参与调节，实际电池电流会随工作条件变化。

**为什么小电流目标能对应几十瓦 PD 输入。** 充电电流与整机负载电流是不同的量。本机记录中，PD 输入约40 W时，电池电流可以降至几十 mA；充电限流值不代表整机供电功率上限。

**为什么保留非零值。** 本机短时对照中，`0x14=0` 时即使将电压目标提高至17600，电池仍持续放电；`0x0040` 配合电压目标维护则恢复了 PD 供电。本方案据此保留非零电流目标，代价是电池仍可能有小电流充入。

**为什么选 `0x0040`。** 该值已在本机试用。原探测脚本依次尝试64、128、256，首个成功读回值为64便停止；因此它确定的是可用参数，并未测定硬件最小刻度。脚本将其标称为64 mA；寄存器到实际电流的换算取决于具体器件和采样电阻，参考 ISL9238A 手册中 `0x0040` 在10 mΩ配置下对应64 mA。

## 控制链

前期 ACPI/EC 离线分析找到限充命令、停充时电流目标清零及电压目标跟随电池电压的路径。后续运行时试验得到有效参数组合：纯 PD 且 `State=6` 时，将零电流目标 `0x14` 改为 `0x0040`，并把过低的 `0x15` 目标提高至 17000。

脚本通过 ASUS WMI 与共享 EC SMBus 邮筒访问，检查目标芯片 ID `0x0049:0x000C`，使用原脚本的地址白名单、参数范围和进程间互斥。该 ID 尚不足以唯一确定具体芯片型号。现有结果确认本机的软件运行时修复有效，完整板级电路和长期电池影响仍需更多实测。

当前脚本将 `0x15` 目标设为 **16400 mV**，读数与目标不一致时更新，包含将旧的 17000 mV 降至新目标。`0x14=0x0040`、触发条件和恢复流程保持原方案。通信处理包括：WMI 返回空数据时报错，SMBus 等待超时后中止本轮。这些补丁通过离线模拟检查，真机效果由维护者验证。

## 已知问题：非零充电目标

`0x14=0x0040` 保留非零充电目标，可能使电池缓慢续充并超过用户设置的电量上限。当前使用 16400 mV 电压目标，实际稳定电量与电池电流需通过设备观察确认。上述 15–27 mA 为原方案的记录读数，16400 mV 版本待真机复测。
