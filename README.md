# ASUS PD Charge Limit Guardian

**华硕 GU603VV：保留电池限充，让 USB-C PD 在停充后继续供电。**

[English](README.en.md) · [原理与验证记录](docs/INVESTIGATION.md) · [贡献说明](CREDITS.md)

我在 ROG 幻16 / Zephyrus G16（2023，GU603VV）上遇到了这个问题：设置电池充电上限后，充到上限，PD 输入会降到 **0 W**，电脑转而消耗电池；电量下降后再恢复充电，如此循环。圆口适配器没有相同现象。

这个工具通过华硕已有的 WMI 接口，在特定停充状态下调整充电控制器的运行时参数。维护者报告：原版脚本开启后，PD 输入恢复到约 **40 W 以上**的整机负载水平，电池电流从约 **2.8–3.0 A 放电**降至 **15–27 mA**。它提供了一个已经在这台机器上奏效的软件绕行方案，不需要刷 BIOS。

> **适用范围：仅 GU603VV、BIOS `GU603VV.315`。** 当前代码包含固定 EC 地址，启动时会检查机型与 BIOS，并在写充电参数前检查芯片 ID。其它机型、其它 BIOS 均未验证，不应通过删除检查来尝试。
>
> **版本说明：** 原始修复和界面由维护者在真机使用；本次公开版 `v0.2.1` 增加了通信超时、错误检查和写后读回验证。这些新增处理经过离线模拟测试，尚未重新进行真机回归。请先保持自动启动关闭，人工确认效果。

## 使用

需要 Windows 10/11、Windows PowerShell 5.1、管理员权限，以及系统中可用的华硕 `root\wmi:IecToolkitInterface`。工具自身不安装第三方底层驱动；该 WMI 接口是否存在取决于机器已有的软件和固件环境。

1. 下载仓库 ZIP，解压到一个固定目录。
2. 双击 **`PD限充不断流开关.bat`**，在管理员提示中确认运行。
3. 保持你原有的 MyASUS / G-Helper 电池上限，点击 **开启修复**。初次使用不要勾选自动启动。
4. 通过外部数显线或功率计观察输入功率，同时查看电池充放电趋势。界面的“修复参数已确认”只表示寄存器读回符合预期，不是对实际输入功率的测量。

关闭面板不会停止独立的后台守护。再次运行启动器可重新打开面板。

### 自动启动与退出

- 面板上的“开关机保护”实际是**当前用户登录后自动启动守护**，不是关机期间继续运行。勾选后创建计划任务 `ASUS_PD_ChargeLimit_Guardian`。
- 点击 **关闭并恢复出厂**，停止守护、移除自动启动任务，并按当前 EC 状态尝试恢复原控制参数。恢复失败会显示错误，不承诺任何异常情况下都能完整恢复。
- 使用自动启动时不要移动脚本目录；移动前先取消该选项。
- 若面板无法启动，可在 Windows“任务计划程序”中禁用或删除上述任务，正常重启后检查状态。不要用任务管理器强杀作为常规关闭方式。

## 它具体改了什么

守护只在 `PDIN=1`、`ACIN=0`、`State=6` 时尝试调整目标芯片：

| 项目 | 当前行为 |
| --- | --- |
| 芯片识别 | 厂商 ID `0x0049`、设备 ID `0x000C` |
| `0x14` | 读到零时写入原始值 `0x0040`，原项目按名义 64 mA 解释 |
| `0x15` | 读值低于 16800 时写入原始值 17000（名义 17.000 V） |
| 轮询 | 目标状态约每 2 秒检查；其它状态约每 5 秒检查 |
| 固件 | 不写 BIOS / EC Flash，调整的是运行时寄存器 |

这两个参数沿用维护者已经试验有效的组合。本板实际采样电阻、芯片具体后缀型号、所有工作模式下的电流误差尚未完成独立验证，**不能把名义 64 mA 当作任何情况下的绝对电池电流上限**。

80% 只是一个常见的限充值。项目关注的是**停充后仍可持续从 PD 取电**，不要求用户取消电池保护，也不会替你更改充电上限。

## 已知限制

- 此工具以管理员权限访问 EC/SMBus；打开面板读取充电芯片也会使用邮筒和通道选择器，并非完全无写入的只读监视器。
- 命名互斥体只协调本工具的面板与守护，不能锁住 EC 固件、MyASUS、G-Helper 或其它监控程序的访问。仍存在竞争、超时和状态切换窗口。
- 通信超时、错误状态、芯片 ID 不符或写后读回不一致时，守护停止干预，并尝试恢复。错误记录保存在 `%LOCALAPPDATA%\ASUS_PD_ChargeLimit_Guardian\last-error.txt`。
- 停充状态仍允许很小的非零充电目标。长时间运行是否缓慢超过设定电量，需要继续观察；没有长期电池寿命或高负载稳定性结论。
- PD 输入功率上限仍由适配器、线缆、协议和整机设计决定。本工具不会把 100 W PD 变成 240 W 圆口电源。
- 运行时恢复依赖通信与 EC 状态。正常重启通常会让固件重新初始化，但进程结束本身不等于所有寄存器立即复位。

## 为什么发布

这个问题在公开讨论中存在多年。前期检索未找到可以直接用于这台 GU603VV 的同类运行时寄存器脚本，后来在维护者持续实测及多个 AI 工具协助下完成了目前的方案。这里公开代码和关键观察，方便同型号用户、维修人员和开发者复查。

公开讨论中也有其它机型通过官方固件改善类似现象的记录。各机型的控制路径需要分别核对；讨论与资料链接见[研究记录](docs/INVESTIGATION.md)。
